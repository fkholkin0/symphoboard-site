# symphoboard-site

Сайт проекта [[Symphoboard]] — афиши классических концертов Москвы.
Публикуется на GitHub Pages, домен **[shymphoboard.ru](https://shymphoboard.ru)**.

Продуктовый код (Chrome-расширение, Apps Script) живёт отдельно и приватно:
`github.com/fkholkin0/Symphoboard` → `~/Projects/Symphoboard`.
Здесь — **только сайт**. Секретов и бэкенд-конфигов тут быть не должно.

## Что сейчас

Заглушка (`index.html`): название, одно предложение о проекте, ссылка на канал,
блок «скоро здесь» про будущую инструкцию.

## Что дальше

Сайт помогает **слушать** музыку. Два разных жанра текста, их не смешивать:

- **«Как слушать вообще»** — входная инструкция, пишется один раз, живёт на главной.
- **Разбор произведения** — много коротких, каждый на своей странице: что автор
  хотел сказать, на какие звуки обратить внимание, как вещь устроена во времени.

Разбор привязан к **произведению**, а не к концерту: Пятая Чайковского пишется
один раз и переиспользуется каждый раз, когда её играют.

## URL разборов

```
/guide/<композитор>-<произведение>/
/guide/tchaikovsky-piano-concerto-1/
```

Правила:

- **Только латиница, только английский.** Кириллица в URL превращается
  в `%D1%87%D0%B0…` при копировании в Telegram и выглядит мусором.
- Нижний регистр, слова через дефис.
- Фамилия композитора в общепринятой английской транслитерации:
  `tchaikovsky`, `shostakovich`, `rachmaninoff`, `prokofiev`.
- Жанр по-английски: `symphony`, `piano-concerto`, `violin-concerto`,
  `string-quartet`.
- Номер — цифрой в хвосте. Номер опуса и тональность не включаем,
  пока они не нужны для различения.

**Slug неизменен после публикации.** Ссылки уходят в Telegram-канал,
переименование их ломает. Ошибся — заводи редирект, не переименовывай.

## Связка с ботом

Карточка концерта в Telegram знает программу. Если для произведения из
программы есть разбор, карточка даёт на него ссылку — канал гонит трафик
на сайт, сайт делает канал полезнее.

Ключ связки уже существует в бэкенде: `canonical_key` вида
`чайковский|концерт для фортепиано №1` (см. `gas/Works.gs` и
`tools/normalize_works.py` в приватной репе). Он снимает разнобой
написаний — «Симфония No. 3» против «Симфония № 3».

**Slug хранится колонкой в листе `music_description`, а не вычисляется
на сайте.** Алгоритм канонизации уже продублирован в двух местах
(`Works.gs` и `normalize_works.py`), и в коде прямо написано «при правке
менять оба места». Третья копия в генераторе сайта неизбежно разъедется —
и битые ссылки посыплются в канал. Заполняем slug один раз при заведении
произведения, сайт и бот просто читают колонку.

## Как устроено

Статика без сборки. Никаких зависимостей, шрифты системные, стили инлайном
в `<head>`. Тёмная тема через `prefers-color-scheme`.

```
index.html    вся страница целиком
CNAME         кастомный домен для Pages — не удалять
.nojekyll     отключает Jekyll, чтобы Pages отдавал файлы как есть
```

## Работа с репой

```bash
cd ~/Projects/symphoboard-site

# посмотреть локально
python3 -m http.server 8000     # → http://localhost:8000

# выкатить
git add -A && git commit -m "..." && git push
```

**Пуш в `main` = деплой.** GitHub Pages пересобирает сайт сам,
обычно 30–60 секунд. Отдельного CI нет и не нужно.

Статус выкатки:

```bash
gh api repos/fkholkin0/symphoboard-site/pages/builds/latest --jq '.status, .error.message'
```

## Домен

`shymphoboard.ru` куплен через **Domenus** (NS: `ns1/ns2.domenus.ru`) —
DNS-записи правятся в панели регистратора, не здесь.

Записи, которые должны стоять на апексе:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | fkholkin0.github.io. |

Проверка:

```bash
dig +short A shymphoboard.ru
gh api repos/fkholkin0/symphoboard-site/pages --jq '.html_url, .https_enforced, .protected_domain_state'
```

Домен и файл `CNAME` должны совпадать. Если поменять домен в настройках Pages
через веб-интерфейс, GitHub сам перепишет `CNAME` коммитом — тогда `git pull`
перед следующей правкой.
